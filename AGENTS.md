# AGENTS.md

Guidance for AI coding agents working in this repository. Workspace-wide rules (data layout, units, **parity with LocMoFit.jl**, working with the owner) are in `../AGENTS.md`; read that first.

## What this is

**LocMoFitPy** is the JAX port of LocMoFit.jl (`../LocMoFit.jl`). It fits a static parametric geometric model to one site's localizations by maximum likelihood and **should give the same results as LocMoFit.jl**. It is meant to be called from MATLAB (SMAP, via `pyenv`; see `run_locmofit.m`) and from Python (SMAPpy). Python is capped at the newest version the **latest MATLAB release** supports through `pyenv` (R2026b → 3.14, so `<3.15`). Raise the cap when a new MATLAB release supports a newer Python. Once the lab moves to SMAPpy, follow SMAPpy's Python version instead. Everything else (JAX) tracks the latest stable releases (Compatibility in `../AGENTS.md`).

One name in every layer since 2026-11-04: the folder `LocMoFitPy`, the GitHub repo `lanceXwq/LocMoFitPy`, the distribution `LocMoFitPy`, the import `locmofitpy`. Until then the repo, the distribution and the import were `LocMoFitPy2`/`locmofitpy2`; GitHub redirects the old repo URL, and SMAP's `WeiMoFit` still expects the old folder.

Stack: `jax` only (since 2026-10-28; Equinox and optax were dropped when the models moved to a flat parameter vector and the optimizer to an own BFGS loop). Environments are managed by **pixi** (`pyproject.toml` → `[tool.pixi.*]`).

## Commands

Run from the repo root; the tests read CSVs by relative path.

```sh
pixi run -e dev python -m pytest tests -k "not cuda12"   # CPU tests, about 45 s
pixi run -e dev ruff check src tests
pixi run -e dev mypy src
pixi run -e cuda12dev python -m pytest tests/test_fit_cuda12.py   # Linux + CUDA 12 only (skipped without a GPU)
pixi run -e dev python benchmarks/speed/speed.py                 # speed of the loss, its gradient and the fits
pixi run -e dev python benchmarks/speed/session.py               # a fresh session: import, first fits, memory
```

Use `python -m pytest`, not the `pytest` entry point. Console-script shebangs in `.pixi/envs` break whenever the folder is moved.

The package mirrors LocMoFit.jl's design (2026-10-28), so that a change there is ported module by module.

## Models and parameters

As in LocMoFit.jl (its `AGENTS.md`, Adding or changing a model): a model only describes a shape; its parameters live in a flat vector, mapped by `ParameterMap` to a dict `theta` of scalars. A simple model subclasses `SimpleModel` and defines `shape_parameters()` (names and defaults), `unit_points(shape, spacing=, dtype=)` (NumPy, built **once from the starting values**, or from `point_params` where given: the point count, `ceil(circumference/spacing)` or `ceil(area/spacing²)`, is fixed for the fit), `local_points(unit, shape)` (JAX, the (M, 3) points in its own frame), `shape_quantities(suffix)` (the shape's quantities with their default priors; a size takes `SIZE_PRIOR`, the log-normal) and `shape_summary`, and gets the pose and blur (`x, y, z, shape…, vx, vy, sigma`). The starting axis comes from the `axis` of `params` as `(theta, phi)`, kept as `theta`, `phi`, and centers the tangent chart; `theta`, `phi` are not parameters, and `Fixed()` on the axis holds `vx`, `vy`. A `Composite` and the presets work as in LocMoFit.jl, with `Tied("r1")` for equal quantities. No bounds or penalties (the owner's decision, 2026-11-14: proper priors, no hard bounds). Add a new model to `_MODELS` in `models.py` under LocMoFit.jl's name.

**Mirror every model, default, prior, or loss change in LocMoFit.jl** (see the parity section in `../AGENTS.md`), or say explicitly that you did not.

## Conventions

- Style (root `AGENTS.md`, Style guide): PEP 8, formatted with `pixi run -e dev ruff format src tests` at 79 characters (`[tool.ruff] line-length = 79` in `pyproject.toml`; ruff skips the gitignored `_*profile.py`) and checked with `pixi run -e dev ruff check --select E,W,I --ignore E501,W505 src tests`. Comments and docstrings have one line per paragraph, list item or signature, with no hard line breaks, so they may exceed 79 characters; commented-out code keeps its lines. The math names (`X`, `R`, `D`, `M`, …) are not renamed for now (the owner's decision: after parity), so the naming rules (`N`) are not part of the check; `DoubleRing`, `SpCapRing` keep LocMoFit.jl's names.
- **Data are `(N, D)` (rows are localizations)**, the transpose of LocMoFit.jl. Precisions are per-axis standard deviations of the same shape, in nm. For 2D input, the model points are truncated to their first 2 columns.
- Parameter names are ASCII (`theta`, `phi`, `alpha`, `sigma`), as in LocMoFit.jl since 2026-10-28 (SciML style: no Unicode in public names).
- `dtype` defaults to `"float64"` (since 2026-10-29, as in LocMoFit.jl; `"float32"` is an option). float64 calls `jax.config.update("jax_enable_x64", True)`, which is **process-global and sticky**: it affects every later JAX call in the same Python process, including a long-lived MATLAB `pyenv` session, so with the default every fit switches it on.
- Everything under `bfgs` is jitted. `run_locmofit` compiles once per model structure (`loss.model_key`), parameter names, padded sizes (`loss.bucket`) and the static options (`max_iter`, `tol`, `history`, background, prior or none), and reuses the compiled fit for every site that matches; the data are arguments, never constants baked into the function. The loss must be pure and traceable: no Python branching on traced values, no `print` (use `jax.debug.print`). If you change `log_likelihood`, change `_ll_bwd` with it: the gradient tests (central differences) and the padding test check them together.
- The value `run_locmofit` returns must stay MATLAB-convertible: a `dict` of NumPy arrays, Python scalars, lists and dicts (`parameters`, `signal_fraction`, `weights`, `components`, `loss`, `model_points`, `iterations`, `retcode`, `history`). Never return JAX arrays.
- Ask before adding dependencies (they go in `pyproject.toml`, and `pixi.lock` changes with them).

## Testing

- `test_models.py`, `test_loss.py` and `test_fit.py` port LocMoFit.jl's suite: the orientation chart against Rodrigues' formula; the model points against their geometry; composites, holding and ties; the loss against an independent loop implementation of the posterior, with its log prior by plain formulas (each distinct variant on every model in 3D, with and without background: the default priors; the fractions' prior replaced (symmetric, one alpha per fraction) or flat; flat sizes; every other kind of prior; in 2D the default priors only, since the log prior does not depend on D); the fraction prior's optimum (two rings far apart, only the share free, no background: (n2 + alpha − 1)/(n + 2(alpha − 1)), and n2/n for the flat Dirichlet(1); also what a fit without a background returns); priors (the fit ends at a prior's mode where the likelihood does not depend on the quantity; what `params` and the prior types refuse); float32 at 40 µm against the rounding bound; the change of length unit ((D + J/N)·log L with J log-normal priors); JAX's gradient against central differences (the default priors and every other kind, a tie and a held axis, no background, 2D); `run_locmofit` (held values, history, ties); `point_params` (the point count from it, held or not, with a tie; the start unchanged); fits of the tutorial data from the moved start, within LocMoFit.jl's tolerances (from its accuracy benchmark); and that the padded loss and gradient `run_locmofit` uses equal the exact ones (SpCapRing, whose ring and cap give both kinds of component block, in 3D and 2D). `test_start.py` ports LocMoFit.jl's tests of the starting values (noise-free ring, cap and two rings with exact expected starts; the ring's and the cap's scores against loops over the derivation's formulas; `start_names` against what `estimate_start` returns; `fit_problem` with given, held and tied values, a given axis, 2D and a model without an estimate of its shape, which gets only its position), and `test_fit.py` fits the 3D tutorial sites from the estimated start, which must reach the optimum of the moved-start fit (its loss in `tests/data/julia_fits.json`, which the tutorial fits match) within 0.01 per localization.
- **Parity:** the starting values estimated from each tutorial site must equal LocMoFit.jl's to 1e-9 (`tests/data/julia_starts.json`). Each tutorial fit (float64) must equal LocMoFit.jl's (`tests/data/julia_fits.json`): the same iterations, the loss to 1e-10 and the parameters to 1e-6. Both use the same BFGS and line search, so they take the same path; on 2026-10-28 they agreed to 12 digits. Regenerate both references with `julia --project=../LocMoFit.jl tests/data/julia_fits.jl` when LocMoFit.jl's fit or estimate changes (on the branch `priors`, from LocMoFit.jl's branch `priors`).
- In float32 the paths part from LocMoFit.jl's, and in both packages float32 fits can stop early when the loss stops changing (`NOTES.md`; accepted, float64 is the default), so there is no float32 fit test.
- Fixed inputs, no RNG (`common.pseudo`); x64 is enabled for the tests (`common.py`).
